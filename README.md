# rendering-patterns

CSR・SSR・SSG などのレンダリング方式を、Next.js 16 で書き分けて比べるサンプルです。
どのページも「時刻を表示するだけ」にそろえて、方式の違いだけが見えるようにしています。

- Next.js 16.4.2（App Router）/ React 19.3
- Cache Components 有効（`create-next-app` の初期設定のまま）

## 動かし方

違いは本番ビルドでしか正しく見えません。`next dev` ではビルド時の事前生成が行われないためです。

```bash
npm install
npm run build   # ルート表の記号で、各ページがどう作られたか分かる
npm start       # http://localhost:3000
```

## 観察のしかた

| 見るもの | 方法 |
|---|---|
| HTML がいつ作られたか | ページをリロードして、表示される時刻が変わるか見る |
| 最初に届く HTML の中身 | `curl -s http://localhost:3000/<path>` で、時刻が HTML に入っているか見る |
| ハイドレーション | `curl` の結果では「未完了」、ブラウザでは「完了」になる。ボタンは完了後にだけ反応する |
| JS がない状態 | DevTools のコマンドメニュー（`Cmd+Shift+P`）で `Disable JavaScript` を選び、リロードする |

ハイドレーションは一瞬で終わるので、普通に開いても切り替わりは目で追えません。
JS を無効にすると、ハイドレーションが起きない状態をそのまま見られます。

- SSR・SSG: 時刻は表示されるが、ハイドレーションは「未完了」のまま。ボタンを押しても反応しない
- CSR: 「読み込み中…」のまま何も表示されない

## CSR（`/csr`）

中身をブラウザで JS が描画します。

- `app/csr/client-clock.tsx` は `"use client"` のコンポーネントで、`useEffect` の中で `/api/now` から時刻を取得します
- `useEffect` はブラウザでしか動かないので、サーバーの HTML には「読み込み中…」しか入りません
- ページの枠（見出しや説明文）はビルド時に事前生成されます。App Router では「ページ全体が空の HTML」にはならず、データの部分だけがブラウザで描画されます

| 観察 | 結果 |
|---|---|
| リロード | 時刻が毎回変わる |
| `curl` | 時刻は入っておらず「読み込み中…」 |

## SSR（`/ssr`）

リクエストのたびにサーバーで HTML を作ります。

- `await connection()` で、ここから先をリクエストが来るまで実行しないよう指定しています
- `export const instant = false` で、ページ全体をリクエスト時まで待たせることを許可しています
  - Cache Components では、ページの一部でも事前生成できるように作るのが基本です。これを外すと、「事前生成できる部分がない」としてビルドが失敗します
  - 本来は、動的な部分を `<Suspense>` で囲んで残りを事前生成するのが推奨です。これは PPR の話なので、別のサンプルで扱います

| 観察 | 結果 |
|---|---|
| リロード | 時刻が毎回変わる |
| `curl` | 時刻が HTML に入っている。ハイドレーションは「未完了」 |

## SSG（`/ssg`）

ビルド時に HTML を作って置いておきます。

- ページの先頭の `"use cache"` で、ページ全体の描画結果をキャッシュします。ビルド時に1回実行され、その結果が配られます
- `export const ensureStatic = "navigation"` で、ページ全体が事前生成されていなければビルドを失敗させます。うっかり動的な処理を足したときの柵です
- `cacheLife("max")` は「30日たったら裏で作り直す」設定です。ビルドのルート表にも `Revalidate 30d` と出ます
  - Cache Components には「二度と作り直さない」設定がないので、厳密にはこれは ISR です。Next.js 16 では SSG と ISR が同じ仕組みで、違いは作り直すまでの期間だけです

| 観察 | 結果 |
|---|---|
| リロード | 時刻はビルドした時刻のまま変わらない |
| `curl` | 時刻が HTML に入っている。ハイドレーションは「未完了」 |

## ISR（`/isr`）

SSG で作った HTML を、期限が過ぎたら裏で作り直します。

- 書き方は SSG と同じ `"use cache"` で、`cacheLife` の期限だけを短くしています（`revalidate: 10`）
- 期限が過ぎた後の最初のアクセスには、古い HTML が返ります。そのアクセスをきっかけに裏で作り直し、次のアクセスから新しい HTML が届きます（stale-while-revalidate）
- `stale` を30秒未満にすると、事前生成の対象から外れて動的な扱いになります。そのため `stale: 30` にしています

本番ビルドで確かめた結果です。

| 経過時間 | リクエスト | 表示される時刻 |
|---|---|---|
| 0秒 | 1回目 | ビルド時の時刻 |
| 12秒 | 期限切れ後の最初 | ビルド時の時刻（古い版） |
| 13秒 | その次 | 12秒時点で作り直した時刻 |

期限を待たずに更新したいときは、`cacheTag` でタグを付けて `updateTag` / `revalidateTag` で消します（`/ppr` の価格で使います）。
